# 개발 방식 결정 메모

작성일: 2026-09-24 · 상태: 결정 대기

## 1. 결정할 것

포토그래핑 MVP(플랜 5절 범위)를 **누가, 어떻게 만들 것인가**. 이 결정에 따라 일정(7절)과 비용(12절)이 달라집니다.

## 2. 선택지 비교

| 항목 | A. 직접 개발 | B. 외주 개발 | C. 기술 공동창업자 | D. 하이브리드 (노코드 + 부분 외주) |
|---|---|---|---|---|
| 한 줄 설명 | 본인(또는 팀)이 코드 작성 | 에이전시·프리랜서에 발주 | 지분을 나누고 개발자를 영입 | 핵심 화면은 노코드(FlutterFlow 등), 채팅·본인인증 같은 어려운 부분만 외주 |
| MVP까지 기간 | 개발 경험에 따라 10~20주 | 8~12주 (견적·계약 2~3주 별도) | 영입 1~3개월 + 개발 8~12주 | 8~14주 |
| 초기 현금 지출 | 인프라비만 (월 수만~수십만 원) | 수천만 원대 (모임·채팅·본인인증 포함 시 후반대) | 낮음 (지분으로 보상) | 노코드 구독 월 수만 원 + 부분 외주 수백만~1천만 원대 |
| 출시 후 수정 속도 | 빠름 | 느림, 건당 비용 | 빠름 | 노코드 부분은 빠름, 외주 부분은 느림 |
| 제품 통제력 | 높음 | 낮음 (명세에 없는 건 안 만들어짐) | 높음 | 중간 |
| 가장 큰 리스크 | 개발 역량 부족 시 일정이 늘어짐 | 출시 후 운영·수정할 사람이 없음 | 맞는 사람을 못 찾으면 시작조차 못 함 | 노코드 한계(채팅, 지도, 이미지 처리)에 부딪히면 다시 만들어야 함 |
| 적합한 경우 | 본인이 앱 개발 경험이 있거나 배울 시간이 있음 | 자금이 있고 빨리 시장 반응을 보고 싶음 | 장기적으로 회사를 키울 계획 | 자금이 적고 빨리 검증만 하고 싶음 |

## 3. 판단 질문

아래 4개에 답하면 선택지가 좁혀집니다.

1. **앱을 직접 만들어 본 경험이 있나요?** (Flutter/React Native로 화면 하나라도)
   - 예 → A 또는 C
   - 아니오 → B, C, D
2. **지금 쓸 수 있는 예산이 얼마인가요?**
   - 1천만 원 미만 → A, C, D
   - 3천만 원 이상 → B 가능
3. **출시 후에도 매주 앱을 고칠 사람이 있나요?**
   - 아니오 → B는 위험. 유지보수 계약을 포함해야 함
4. **이 앱을 몇 년짜리 사업으로 보나요?**
   - 3년 이상 → C를 진지하게 검토
   - 우선 검증만 → D 또는 축소한 B

## 4. 추천

인터뷰(1~2주차)가 끝나기 전에는 **돈이 드는 결정을 미루는 것**을 추천합니다. 검증 결과에 따라 MVP 범위가 줄어들 수 있고, 그러면 견적도 달라집니다.

인터뷰 결과 모임 기능이 핵심으로 확인되면:

- **자금이 있으면 B(외주)**, 단 계약에 아래 3가지를 반드시 넣습니다.
  - 소스코드와 앱스토어 계정 소유권은 발주자
  - 출시 후 3개월 유지보수 포함
  - 기능 명세는 이 저장소의 플랜(5절 MVP 범위)과 와이어프레임을 기준으로 함
- **자금이 적으면 D(하이브리드)** 로 클로즈드 베타까지만 가고, 반응이 확인되면 그때 B 또는 C로 다시 만듭니다.
- **개발 경험이 있으면 A**. 스택은 플랜 6절대로 Flutter + Supabase. 채팅과 본인인증은 직접 만들지 말고 서비스(Supabase Realtime, PASS 연동 대행)를 씁니다.

## 5. 외주를 선택할 때 견적 요청서에 넣을 것

- 이 문서와 `01-service-plan.md` 5절(MVP 범위), `../wireframes/index.html`
- 플랫폼: iOS + Android, 단일 코드베이스
- 필수 연동: 카카오·애플 로그인, PASS 본인인증, 카카오맵, 이미지 CDN, 푸시(2단계여도 구조는 미리)
- 관리자 페이지: 신고 처리, 사용자 정지, 모임 삭제, 공지 등록
- 산출물: 소스코드, 빌드 방법 문서, DB 스키마, 앱스토어 등록 대행 여부
- 일정: 개발 7주 + 베타 수정 2주
- 견적은 3곳 이상 비교, 기능별로 나눠 받기 (채팅과 본인인증이 비싸면 2단계로 미룰 수 있도록)
